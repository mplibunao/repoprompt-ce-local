## 4. Port upstream PR 1473 with distribution reconciliation

- Decision: port every hunk of upstream commit `dbac8c29e`. It adds `ApplyEditsStatus.noChange` (`"no_change"`). A batch whose edits match but leave the bytes unchanged returns `no_change` with `editsApplied: 0`, no diff, and its outcomes. `ApplyEditsService` writes only when the bytes differ, and a missing file still counts as a creation. The MCP receipt shows ℹ️ and "No net change", successful outcome lines read "matched (no net change)", and the Agent Mode edit card shows `no_change` as neutral. The two redundant `package` modifiers inside `package extension ApplyEditsResult` are dropped, as upstream does, and visibility is unchanged. Source: approved plan.
- Decision: the distribution's single/rewrite literal no-op (`unchangedResult`, from commit `812dd2cd2`) also reports `no_change`, so every result without a write reads the same way. Before, it reported `success` with 0 applied, and the MCP receipt showed ❌. The consumers of that path key on counts or on the commit boundary rather than on `success`. `MCPApplyEditsToolProvider` uses counts, and its `editsApplied == 0` early return skips review and write. The protected-mutation journal settles on the commit boundary. Source: approved plan, checked by the plan critique and the correctness review.
- Decision: the standalone headless backend (`Sources/RepoPromptMCP/DirectHeadlessCapabilityBackends.swift`) reports `mutation_acknowledgement.mutation` as `not_applied` when no edit applied. It said `applied` unconditionally, which would sit beside `status: "no_change"`. No existing test calls the real `applyFileEdits`, so this one-line change has no test. Source: approved plan.
- Decision: Agent Mode gets only the edit-card mapping. A reopened conversation shows a non-error no-change result as success with "0/N edits", because compact persistence keeps the execution status, and upstream behaves the same. The narrow fix, if wanted later, is in the `statusWord` closure of `AgentToolResultPersistencePolicy.sanitizedToolResult`. Source: approved plan, after the plan critique traced the status chain.
- Decision: tests. The new `Tests/RepoPromptDomainRuntimeTests/ApplyEditsNoChangeTests.swift` uses upstream's recording host. `testNetZeroBatchesKeepMatchesButNeverWrite` states each row's expected outcome statuses instead of upstream's count-dependent expression. `testUnicodeNormalizationChangeIsNotAByteIdenticalNoOp` also checks the stored bytes. Upstream's whitespace-and-creation test is split into `testWhitespaceOnlyMutationStillWrites` and `testMissingEmptyFileIsCreated`, which protect different write decisions. In the root suite, `testNoChangeReceiptUsesExplicitStatusInDecodedAndFallbackResults` renders a receipt with a successful and a failed outcome through both formatter branches, with a string-valued `total_lines_changed` forcing the raw-object branch. `testRequestsThatLeaveTheFileAsItIsReturnAnUnchangedResult` now expects `no_change`. The plan's service-level single/rewrite no-op test was dropped, because those paths return `editsApplied == 0` and the existing guard already blocks the write. Source: approved plan.
- Evidence: with the engine and service at the 1304 commit (the enum case kept so everything compiles), every net-zero row fails. Each reports `success` or `partial`, counts the matches as applied, has no outcomes or note, and writes once. The Unicode, whitespace, and creation guards pass both ways. With the port, `ApplyEditsNoChangeTests` passes 4/4, `ApplyEditsCoreRecoveryTests` 23/23, `ApplyEditsApprovalCancellationTests` 1/1, `MCPReadMutationPathContractTests` 50/50, `DiffChunkTextApplierTests` 4/4, and `DiffGenerationUtilityRoutingTests` 3/3. Format left every file unchanged, lint is clean, and `make dev-swift-build` passes for `RepoPrompt` and `repoprompt-mcp`. Against `dbac8c29e`, the three domain files differ only by `unchangedResult`, the distribution's phase reporting in the service, and the dropped issue reference.
- Evidence: the correctness review found nothing. It checked the write paths, empty-file creation, error precedence in the edit card, both formatter branches, and that no tool description or CLI help lists apply_edits statuses. The refactor review weighed consolidating the formatter's three `no_change` checks and sharing construction between `unchangedResult` and the net-zero branch, and rejected both to stay close to upstream.
