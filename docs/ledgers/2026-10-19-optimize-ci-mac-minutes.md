# CI macOS runner-minute optimization

- Start date: 2026-10-19
- Metric: macOS runner minutes per CI workflow run: the sum of the elapsed time of every macOS job in the run, with parallel jobs counted separately and queue time left out.
- Reported for: Markdown-only pull requests, code pull requests, release-candidate pushes, pushes to `main`, and runs that re-test a Git tree that already passed.
- Stop criterion: a Markdown-only pull request uses no macOS minutes beyond guardrails, which need macOS, and the conductor tests, one of which checks wording in two Markdown files; the code pull request median is at most 40.8 minutes, 30% below the baseline; and no run re-tests a tree that already passed. The loop also stops when the oracle reports diminishing returns, or after five iterations.
- Scope: `.github/workflows/ci.yml`, `.github/workflows/xcode-workspace.yml`, `Scripts/ci_app_test_runner.py` and its self-test, the Makefile targets CI calls, and the Landing section of `CONTRIBUTING.md`. App code and test contents are out of scope.
- Constraint: a release candidate still needs a green hosted run on its own tip before it lands.
- Measurement: the GitHub API's run list (`repos/mplibunao/repoprompt-ce-local/actions/workflows/ci.yml/runs`) and each attempt's jobs (`actions/runs/<run>/attempts/<n>/jobs`). Each job counts when one of its runner labels starts with `macos`. A pull request run is Markdown-only when every file its pull request changes ends in `.md`. A run's tested tree is its head commit's tree for pushes, and for pull requests the merge of the head into the pull request's base branch as of the run's start. When that base is another pull request's branch, as in a stack, its tip at run time can't be recovered, so the run has no known tree and stays out of the repeat count. Skipped jobs count zero. The medians use successful first attempts; cancelled, failed, and rerun attempts are totalled separately.
