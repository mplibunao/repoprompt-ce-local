## 1. Drop empty names from selection-graph contributions

- Decision: `CodeMapSelectionGraphContribution.canonicalNames` drops names that are empty after NFC normalization. Anonymous C enums put `""` into an artifact's defined type names, the manifest encoder wrote it, and the decoder rejects empty names. No version number changes, because no stored contribution that decodes today contains `""`. Source: approved plan.
- Decision: the new test doesn't assert that the artifact's enum cases and API description are unchanged, which the plan's oracle lists. The test builds that artifact itself and the manifest path never modifies it, so those assertions would compare the test's input with itself. The test instead asserts that the input artifact still carries the empty name, so it keeps exercising the contribution path if the generator changes later. Source: the implementing agent's judgment, accepted by the orchestrator and the review.
- Evidence: `testAnonymousEnumContributionRoundTripsWithoutEmptyGraphNames` fails on the unfixed source with `recordValidation` from `publish()` and passes with the fix. `make dev-format`, `make dev-lint`, `make dev-swift-build PRODUCT=RepoPrompt`, and `make dev-test` with `RepoPromptTests.CodeMapRootManifestTargetCacheTests` (8 tests), `RepoPromptTests.CodeMapArtifactContainerTests` (9), and `CodeMapGoldenTests` pass. The review and the refactor analysis found nothing.

## 2. Decode the temporary manifest before the rename

- Decision: `publishCurrentManifest` reads and decodes the synced temporary file before the rename and no longer reads the manifest after it, so each publication still decodes once. After the rename only file identity can reveal a change: the renamed file must match the validated temporary file on every field except status-change time, which the rename updates (`ManifestFileIdentity.matchesIgnoringStatusChange`), and must be unchanged after the `afterPublishRename` hook. Source: approved plan.
- Decision: a change to the file between the last check before the rename and the first identity sample after it isn't detected. A review asked for a second content read after the rename; it was declined, because the plan accepts that window to keep one read per publication. Source: approved plan.
- Decision: the early `.unchanged` return of a superseded access refresh now sets the DEBUG `succeeded` flag, which the plan's rule ("only when the call returns successfully, including an `.unchanged` result") requires. Source: approved plan, applied by the implementing agent.
- Decision: the temporary-file test flips a magic byte and recomputes the checksum, and expects `invalidMagic`. The plan's oracle flipped any byte and expected `checksumMismatch`, which a store that checked only the checksum before the rename would also pass, while the production failure was bytes with a valid checksum. Source: review finding.
- Decision: `overwriteInPlacePreservingModificationDate` moved to file scope and restores timestamps with `utimensat`. Foundation's `setAttributes` restored the modification time only to the microsecond, and that drift alone made the post-rename test pass on a store that captured the renamed identity too late. A new `resealedManifest(_:changingPayload:)` helper writes the checksum trailer for both tests that need one. Source: the implementing agent's judgment, accepted by the review.
- Evidence: each new test passes on the fixed store and fails on the original store. The temporary-file test also fails on a store whose pre-rename step only validates the checksum, and the post-rename test fails on a store that keeps the old object-and-size check and on one that captures the renamed identity after the hook. `make dev-format`, `make dev-lint`, `make guardrails`, `make dev-swift-build PRODUCT=RepoPrompt`, and `make dev-test` with `RepoPromptTests.CodeMapRootManifestTargetCacheTests` (10 tests) and `RepoPromptTests.CodeMapArtifactContainerTests` (9) pass.

## 3. Count corrupt and insecure manifests and run maintenance once after the first publication

- Decision: `CodeMapRootManifestAccounting` gains `corruptManifestCount` and `insecureManifestCount`, counted per scan for canonical manifest names. A mutating scan doesn't decrement the corrupt count when it moves a file, because callers see the non-mutating scan that follows. Source: approved plan.
- Decision: the process-wide store runs `maintain()` once per process, as a separate task started after its first publication that ran its quota scan, in DEBUG and release builds. Every other store construction keeps the flag off. A truncated or failed pass is logged and not retried. Source: approved plan.
- Decision: the result line, `manifest_maintenance_after_first_publication`, logs at the default (notice) level instead of the plan's info level, and at error level when the pass is truncated or insecure manifests remain. macOS doesn't keep info-level lines in the log store by default, so `log show`, which the plan's live check uses, wouldn't find the line, and the first launch on the production profile would leave no record of its cleanup. The plan's warning level becomes error level, because `Logger.warning` logs at error level. Source: the implementing agent's finding, decided by the orchestrator.
- Decision: a failed pass logs a fixed category per store error, plus the operation label and errno for I/O errors. Every operation label in the store and in `CodeMapSecureFileRemoval` is a string literal, so the line can't carry a path. Source: approved plan. The orchestrator checked the labels during review.
- Decision: a review asked to count a canonical-name symlink as insecure. The scan can't open a symlink and skips it. Declined: the plan keeps the scan's behavior for entries it can't open, and the live check counts files on disk directly. Source: approved plan (decision 7).
- Evidence: `testFirstPublicationCleansCorruptManifestsAboveCap` passes. With only the line that starts the task removed, it times out and leaves 3 corrupt manifests and 4 quarantine files. `make dev-format`, `make dev-lint`, `make guardrails`, `make dev-swift-build PRODUCT=RepoPrompt`, a release-configuration package build (`./conductor package release`, ad hoc signed, build output only), and `make dev-test` with `RepoPromptTests.CodeMapRootManifestTargetCacheTests` (11 tests) and `RepoPromptTests.CodeMapArtifactContainerTests` (9) pass.
