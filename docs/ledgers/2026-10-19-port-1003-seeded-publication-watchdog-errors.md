## 4. Watchdog terminal response ownership

- Decision: `UnixSocketMCPTransport.swift`, `BootstrapSocketConnectionManager.swift`, and `MCPExportWatchdogTestSupport.swift` take upstream's c9778b03 hunks as written, and the transport differs from upstream's post-image only at the `prompt`/`workspace_context` tool check, which no hunk touches. The response ledger keeps a plain `NSLock`. `MCPConnectionManager.swift` takes the terminal context, the protocol requirement, and the abort call. Source: approved plan.
- Decision: in `MCPExportWatchdogIntegrationTests.swift` the new helpers close the class, where upstream puts them before `responseObject(from:)`, because #213 moved that function to `MCPWindowTestSupport`. None of the new code calls it. Source: orchestrator judgment.
- Decision: the pipelined test also accepts a peer-closure POSIX error from its last request, besides the client's `closed` error. Once both terminal errors arrive the server can close the socket before the test client sees EOF, so the request can fail with `EPIPE` or `ECONNRESET` while the code under test behaves correctly. Source: review finding.
- Decision: five review findings are declined, and the code stays as upstream wrote it. Source: orchestrator judgment.
  - Terminal delivery is marked finished before the disconnect, so a queued ordinary frame can start writing in that gap and hold the disconnect behind a backpressured write for up to the existing 30 s stall allowance. Upstream states that socket closure stays best-effort under backpressure and adds no timeout, and the plan keeps both.
  - The read queue records a request ID in the watchdog ledger just before the delivery tracker. If the watchdog seals between the two, teardown reports the request as unanswered although its terminal error went out. The only consumer of that flag is the Context Builder teardown label for a connection the watchdog is already closing.
  - Each rejected explicit-null-ID frame starts an unstructured task to send its error, outside the bounded inbound channel, so a client that sends such frames without reading replies can pile up tasks on its own connection. Conforming clients never send an explicit null ID.
  - The raw-socket tests wait on the suite's existing one-shot signal, which has no timeout, so a transport regression can hang a test instead of failing it. The suite's other tests use the same helper in the same way.
  - The explicit-null-ID socket test skips its transport disconnect when an assertion throws, which matters only after the test has already failed.
