- Decision: liveness for the Claude Code lane comes from bytes the CLI child writes to stdout, with `--include-partial-messages` on, instead of upstream's 30 s timer that runs while the request is pending. The timer also runs while the request waits for the runner's concurrency gate, prepares its launch, or backs off between retries, and it keeps a hung child alive until the 4 h ceiling. A probe of Claude Code 2.1.318 on 2026-11-06 showed that without partial messages the CLI doesn't print anything while the model writes a text block, so a long reply would still be cut off. With partial messages the largest gap between stdout lines was 3.8 s. Source: orchestrator judgment, applying the decision above.

The distribution's `CLIProcessRunner.run` already has `cancelChildOnTaskCancellation`, so the production side is a few lines in `ClaudeCodeProvider`; the cost is upstream's test fixture (about 240 lines), which depends on runner injection and a test launch permission the distribution lacks. After this run's changes the child is stopped anyway: the provider's only caller, `AIQueriesService.sendPrompt`, disposes the provider when it stops reading the stream, and disposal terminates the provider's children. Before, `streamMessage` returned only after the CLI exited, so a cancelled follow-up left its child running to completion. A live check in item 5 measured the child exiting 0.92 s after a cancel. ## 1. Strict Claude stream-json completion

- Decision: `ClaudeCodeProvider.completeMessage` runs the CLI with `--verbose` and stream-json output. `parseStreamJSONCompletionPayload` returns the text of every top-level `assistant` event in order and takes usage and cost from the terminal event. It throws on a malformed or truncated JSON line, on a missing terminal event, and on an error terminal (`type` `error`, `is_error`, a `subtype` containing `error`, or a non-empty `errors`, compared case-insensitively). For a failed run, `extractStreamJSONErrorDetail` returns the terminal's error text, or the last plain-text line when no terminal arrived. The settings connection probes stay on single-JSON output. Source: approved plan.
- Decision: one scanner serves both entry points: a strict mode for completions, which stops at the first malformed line, and a lenient mode for error extraction, which skips malformed lines. Lines starting with `[`, such as `[SandboxDebug]` diagnostics, are never returned as error text. An error terminal with no usable text gives nil on a failed run, so stderr and exit-status handling apply, and "Claude CLI returned an error" on an exit-zero run. Source: implementing agent judgment.
- Evidence: added `OracleTransportActivityPropagationTests` tests `testClaudeStreamJSONPreservesOrderedTopLevelText`, `testClaudeStreamJSONFallsBackToTerminalResultWithoutAnswerText`, `testClaudeStreamJSONRejectsMalformedOrMissingTerminal`, `testClaudeStreamJSONRejectsTerminalErrors`, and `testClaudeStreamJSONExtractsTerminalFailureDetail`; the suite passed 13 of 13. `make dev-format`, `make dev-lint`, and `make dev-swift-build PRODUCT=RepoPrompt` passed. No test was renamed or removed.
- Evidence: the implementing agent's `context_builder` review found one gap after the first round: no table row put a malformed line before an error terminal. The row was added, and the follow-up review found nothing. The refactor review found no material opportunity.

## 2. Runner stdout observer and transport-activity helper

- Decision: `CLIProcessRunner.run` takes an optional `onStdoutChunk` callback, called on the stdout reader's queue right after each chunk is appended and outside any pipe lock; the readers are joined before `run` returns, so no call outlives it. Source: approved plan.
- Decision: new `ProviderTransportActivity.swift` holds the activity result, a throttle (first receipt and every receipt at least 5 s after the last emission; suppressed receipts don't move the timestamp), and `ProviderPendingCompletionStream.make`. The stream starts its completion on the first pull and passes it a reporter. Reports yield throttled activity under one lock, and settlement closes activity under that lock before it yields content and the terminal result (`message_stop`, or `message_incomplete` with the stop reason). Cancelling the consumer, or releasing a started stream, cancels the completion without waiting for it. Source: approved plan, adapting upstream PRs 1276 and 1283.
- Decision: `make` took a `minimumActivityInterval` that only tests changed; item 5 removed it with the checks that needed it. The iterator's `deinit` cancels the producer as well as the inner stream's termination handler, so cancelling on release doesn't depend on how the standard library frees an iterator. Source: implementing agent judgment.
- Evidence: added `ProviderTransportActivityTests` tests `testPendingCompletionOrdersReportedActivityBeforeTerminalOutput`, `testPendingCompletionFailureStopsActivityAndPreservesError`, `testConsumerCancellationCancelsPendingRequest`, `testConsumerCancelledBeforeFirstPullStartsNoRequest`, `testReleasingStartedStreamCancelsPendingRequest`, and `testReceivedBytesThrottleUsesInclusiveInterval`, passing 6 of 6 on four runs; added `CLIProcessRunnerPipeLifecycleTests.testRunObservesStdoutBeforeExitWithoutChangingCapturedOutput` (a real shell child) and extended `testFinishedChildOutputSurvivesDelayedReaders` to compare observed and returned stdout, passing 7 of 7. `make dev-format`, `make dev-lint`, `make guardrails`, and `make dev-swift-build PRODUCT=RepoPrompt` passed. No test was renamed or removed.
- Evidence: the implementing agent introduced each defect a test names, one at a time, and the matching test failed, except one: no test fails when settlement leaves activity open, because the producer yields content, the terminal result, and the finish without suspending, so no later report can land between them. Testing that would need a hook in production code. The `context_builder` review's one finding, a cancellation fixture that couldn't tell a prompt return from one that waits for the completion, was fixed.
- Decision: the refactor review's only suggestion, moving two identical private `Locked` test fixtures into a shared helper, wasn't applied: two private fixtures in separate suites cost less than a new shared test file. Source: orchestrator judgment.

## 3. Claude and CustomOpenAI liveness, monitor tests

- Decision: `ClaudeCodeProvider.streamMessage` returns `ProviderPendingCompletionStream.make`, and Oracle completions add `--include-partial-messages`. Each stdout chunk of each attempt's child reports activity through one reporter that spans all retries. Cancellation is checked on entry, after the MCP config lease, before each attempt, and after each runner result. The retry backoff sleep now ends on cancellation, `mapProcessError` passes `CancellationError` through, and a run counts as successful only when it exits zero without timing out. The child-cancellation contract and the connection probes are unchanged. Source: approved plan; the check after the config lease came from the item's review.
- Decision: `CustomOpenAIProvider` keeps one throttle per stream task, outside its retry loop, and every received SSE line can yield activity before the `event: error` and `data:` filters, so keepalive comments and content-less deltas count. Source: approved plan, as upstream PR 1276.
- Decision: the direct `completeMessage` path sends the same arguments, partial messages included, without a reporter. It has no live caller. Source: implementing agent judgment.
- Evidence: added `ProviderTransportActivityTests.testCustomOpenAIKeepaliveReportsActivityBeforeContent` (a URLProtocol stub that holds the answer back until the keepalive's activity is seen) and `ContextBuilderFollowUpFinalizationMonitorTests` tests `testLivenessRenewedLaneCompletesAcrossInactivityBudgets` (a 10 s budget renewed at 8, 16, 24, 32, and 40 s, still running at 49.9 s, then completing) and `testLaneWithoutFurtherLivenessTimesOut` (alive at 25.9 s, timed out at 26 s with its partial text and one cancellation). The renewed-lane test is issue #4's regression test for a completion next to the watchdog horizon. Suites: `OracleTransportActivityPropagationTests` 13 of 13, `CLIProcessRunnerPipeLifecycleTests` 7 of 7, `ProviderTransportActivityTests` 7 of 7 on three runs, `ContextBuilderFollowUpFinalizationMonitorTests` 9 of 9 on three runs. `make dev-format`, `make dev-lint`, `make guardrails`, and `make dev-swift-build PRODUCT=RepoPrompt` passed.
