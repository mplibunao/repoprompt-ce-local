### 3. Artifact and container contract

- Decision: `CodeMapSyntaxArtifact` has an optional `terraform` payload, which the canonical writer emits as `null` for other languages. The pipeline `artifactSchemaVersion` is 2 for every language, and the artifact container is at version 2 with a 26-field summary that counts every persisted Terraform string and collection entry. `CodeMapPipelineLanguageID.terraform` exists so the container can require a Terraform payload for a ready Terraform key and reject one for any other language. No exhaustive switch needed a new case for it. Source: approved plan.
- Decision: a payload under the wrong language's key fails with its own container error, `payloadLanguageMismatch`, on encode and decode, rather than reusing `keyMismatch`, which means the stored key isn't the requested one. A Terraform key with `readyNoSymbols` is accepted, because the plan requires the payload only for `ready`; extraction returns `ready` for an empty file. Source: orchestrator judgment, from the implementing agent's proposal.
- Decision: the model enforces the outline whitelist of attribute names per declaration kind, in the initializer that decoding also goes through, so neither extraction nor a decoded container can carry a variable's default value or a local's value into an outline. A repeated attribute name is allowed, because a file that parses keeps its outline even when Terraform would reject it. Source: review finding, round 1.
- Decision: the model also requires a block type that matches the declaration kind, a source on every module call, and non-empty argument names and reference parts. Constructors NFC-normalize, deduplicate, and sort argument names and reference parts by UTF-8 bytes, and decoding rejects input that isn't already in that canonical order. Source: orchestrator judgment, from the implementing agent's proposal.
- Decision: no committed test for the whitelist. The way a default value would actually leak is extraction emitting it, and the next item's outline test and goldens cover that from parsed source. Source: orchestrator judgment, following `rpce-test-quality`.
- Evidence: the review loop ran `context_builder` (review) from an Agent session bound to this branch's worktree. Round 1 raised the missing whitelist and a summary test that couldn't tell `blockType` from `kind`, because the fixture's two strings had the same length. Both were fixed, and round 2, on the same chat, found nothing.
- Evidence: the refactor loop ran in a separate bound session with its own `context_builder` chat, after a scout checked for helpers the new code duplicates. Its first analysis led to two simplifications in `TerraformCodeMapArtifact.swift`, and its second to an `addNestedStrings` helper in the container summary. Each was applied from an exported plan by a bound engineer session, and the third analysis found nothing. A throwaway probe, deleted afterwards, showed byte-identical canonical JSON and decoder errors before and after the model simplifications.
- Evidence: `make dev-format` changed 0 files, `make dev-lint` passed, and `make dev-test FILTER=CodeMapArtifactContainerTests` (10 tests), `FILTER=CodeMapSyntaxArtifactTests` (6 tests), and `FILTER=CodeMapGoldenTests` passed, so existing-language goldens are unchanged.

### 4. Extraction

Declarations and outline attributes came first, then references, each through its own review and refactor loops.

- Decision: RepoPromptCodeMapCore registers Terraform: `LanguageType.terraform`, a grammar recipe with stable ID `terraform` and revision `fad991865fee927dd1de5e172fb3f08ac674d914`, and a query over top-level blocks that the engine registers but doesn't run. The `.tf` extension stays unregistered. The app's language-to-pipeline-ID switch got the one case compilation required. Source: approved plan.
- Decision: a `.tf` file fails as a whole with `invalidTerraformSyntax` on an error or missing node, on a JSON-style root, and on an escape that names no Unicode scalar, such as `\uD800`, anywhere outside a heredoc, including in top-level attributes. The grammar's root rule accepts an object without an error node, so the JSON-style root needs its own check. The scanner checks only that an escape's hex digits are present. Source: approved plan for the policy; review findings for where escapes are validated.
- Decision: the non-ASCII heredoc row of `testOutcomePolicy` expects only `invalidTerraformSyntax`, because the pinned scanner leaves a missing `heredoc_identifier` node there. A grammar upgrade that fixes the scanner changes the row. A second heredoc row checks that a heredoc's backslashes aren't decoded. Source: review findings.
- Decision: a nested `source` block makes a module's source `invalid`, top-level attributes add no declarations, and `locals "x" {}` is a header-only `other` declaration. Source: orchestrator judgment, from the implementing agent's proposal.
- Decision: no test for the builder's check that a Terraform outcome comes only from the Terraform language and the reverse. The engine is the only producer of Terraform facts and always pairs them with `.terraform`, so a removed check has no reachable effect. Source: orchestrator judgment, declining a review suggestion.
- Evidence: the first review chat raised two test-oracle gaps and a suspected escape gap, which a throwaway probe confirmed: `\uD800` returned a ready outline in six positions, including a variable default and a template chunk. That chat found the same gap in top-level attributes. After that session was stopped, a third chat, given every earlier finding and fix, asked for the positive heredoc row, and its second round found nothing.
- Evidence: the refactor loop ran in its own bound session and chat, after a scout. The analysis led to two simplifications in `TerraformCodeMapStrategy.swift`: one constructor call for every non-local declaration, and a flag in place of the list of nested block names. A bound engineer session applied them from an exported plan, a throwaway probe of 68 inputs gave byte-identical output before and after, and the follow-up analysis found nothing. The scout also pointed at a range-slicing helper in `CodeMapGenerator` and at strings decoded twice; the analysis didn't take either, because that helper is private and every quoted string is decoded once for validation.
- Evidence: `make dev-format` changed 0 files, `make dev-lint` passed, and `make dev-test` passed for `TerraformCodeMapTests` (3 tests), `CodeMapGoldenTests`, `CodeMapSyntaxArtifactTests` (7 tests), and `CodeMapArtifactContainerTests` (10 tests). `make dev-swift-build PRODUCT=all` succeeded. A throwaway check compiled the registered query against the pinned grammar.
- Decision: references are collected during the same single walk, from every block body, including omitted bodies, defaults, and validation conditions, and never from comments, string text, attribute names, labels, or top-level attributes. Instance selectors, splats, legacy indexes, and parentheses are stripped from an access path, a function result stays opaque, and at most one selector is skipped between a module call and its output name. Source: approved plan, with the parentheses rule from a review finding.
- Decision: provider configuration addresses are skipped only in selector positions: `provider` directly in a `resource`, `data`, `ephemeral`, `action`, or `import` block or a `data` block inside `check`, and `providers` directly in a `module` block. A `locals` attribute or module input with either name keeps its references. A top-level `terraform` block yields no references, so `configuration_aliases` can't become a resource. `ephemeral` and `action` roots aren't resources. Source: approved plan for the selector rule; review findings for the positions, the `terraform` block, and `action`.
- Decision: `import.to`, `moved.to`, and `moved.from` are read as addresses: a resource or data address gives its declaration, and an address inside a module gives only the module call. A `removed.from` gives only a module call that the address continues past, because Terraform requires the removed object to be absent while its module may remain. Source: review findings, replacing the implementing agent's first choice of no references from any of these.
- Decision: three review findings were declined. A parenthesized `iterator` or static address isn't valid Terraform, because HCL's keyword and static-address parsing doesn't unwrap parentheses. `(module.worker[*])[0].endpoint` isn't in the plan's normalization table and degrades to the call reference. A resource type spelled `var` or `local` inside an address would need a provider with that local name. Source: orchestrator judgment.
- Decision: lexical scopes are enter and exit entries on the traversal stack with a count per bound name, the parenthesized levels an enclosing traversal has read are recorded so they aren't read again, and a nested block's frame carries its parent's block type. Each replaces work that grew with the square of nesting depth or header length, which the plan's linear-walk rule forbids. Source: review findings.
- Evidence: the reference review ran through five chats. Each of the first four changed owner when its session's provider restarted while idle during a fix, and the standing recovery started a new bound session with a fresh chat given every earlier finding: `terraform-reference-revi-2C35EA` to `terraform-reference-revi-07F03A`, then to `terraform-reference-revi-337492`, then to `review-terraform-referen-A84093`, then to `review-terraform-referen-F02DFA`. The declaration half's review moved from `terraform-extraction-rev-4161DA` to `terraform-extraction-rev-ABD251` and then to `review-terraform-extract-A72012`, as described above.
- Evidence: throwaway probes, deleted afterwards, measured the linear-work fixes. At 2,000 nested parentheses the traversal loop went from 2,007,008 reads to 2,009; at 1,000 nested binders binding work went from 1,501,500 to 2,000; at 1,000 header comments and nested blocks child reads went from 1,030,014 to 24,014.
