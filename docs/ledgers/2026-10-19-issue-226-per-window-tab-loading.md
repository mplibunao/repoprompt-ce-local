Request: #226 · Plan: `issue-226-per-window-tab-loading-2026-10-19.md`

- Decision: commit reconciliation follows two rules. First, a write owns only the fields it changed from its baseline, which decides what enters the window's copy (a field-level `mergingTab`), what is protected, and what is mirrored. A copy still behind the write's baseline takes the whole document, because losing a committed write is worse than losing unsaved edits made during one submission. Where the write and the copy changed the same field, the write wins. Source: review findings; the merge criterion and the fallback's retention are implementer judgment.
