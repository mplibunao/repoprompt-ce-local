## 1. Freeze a review target for every caller

- Decision: `resolveImplicitContextBuilderGitTarget` returns the discovery snapshot's frozen resolution whenever the snapshot has one, with or without an Agent session. When it has none, it behaves as before: an Agent session gives the missing-target refusal and no session gives no restriction. The plan's section E dropped the Agent-session requirement outright on the premise that every nested run carries a frozen context. Runs started from the Context Builder panel don't: they install the tab's own snapshot (`ContextBuilderAgentViewModel.swift`, the `prepareAndInstallPolicy` call in the discovery start), so dropping the requirement would have refused `git`, including artifact publication, in every panel run on a tab with no Agent session. Source: implementing agent's finding, checked against the code; orchestrator judgment.
- Decision: hydration before the freeze runs only for outside callers, because Agent Mode snapshots are run-scoped and `resolve` already requires them hydrated. Source: implementing agent's judgment from plan section D.
- Decision: `CancellationError` passes through stage 2 of `resolveContextBuilderTab` for every caller, so a cancelled Agent Mode call now reports cancellation instead of an invalid-parameters error. Source: plan section J.
- Decision: the proposed `testOutsideReviewFreezesSelectedCheckoutInsteadOfFirstRoot` lives in `MCPExportWatchdogIntegrationTests`, not the nested-selection suite the plan named. The nested-selection suite calls `resolve` directly and can't catch a missed hydration in `resolveContextBuilderTab`. Source: implementing agent's judgment under `$rpce-test-quality`.
- Decision: an outside call whose `.available` target goes stale between the freeze and admission is refused, as an Agent Mode call already is. It is a narrow race and the existing error names it. Source: orchestrator judgment.
- Decision: for outside callers, `ContextBuilderWorkspaceContext.resolve` checks that every root of the invoking workspace is loaded, whether or not the tab has worktree bindings. The first version checked only when there were no bindings, so a hinted tab in an inactive workspace whose Agent session bound a worktree could freeze against the visible workspace's roots. Agent Mode keeps checking only without bindings: a workspace switch cancels its runs, and a stricter check would refuse an Agent Mode call in a workspace with a root that failed to load. Source: review finding, confirmed by the implementing agent.
- Decision: the freeze doesn't require the loaded roots to equal the invoking workspace's roots. A folder removal whose workspace save fails leaves the root loaded while the workspace no longer lists it (`WorkspaceManagerViewModel.removeFolder`), so equality would refuse every outside call in that workspace until the next reconcile. Known limitation: an outside call on a tab in an inactive workspace whose roots are all loaded by the visible workspace, where the tab's Agent session binds a worktree, freezes a lookup that also covers the visible workspace's other roots. Source: orchestrator judgment.
- Decision: `testOutsideReviewWithForeignStartingSelectionStillRuns` captures the outgoing review request at the Oracle transport and asserts that the per-file diff carries the discovery-selected repository's uncommitted marker and none of the starting repository's. The first version checked only the selection and the absence of final authorization. Source: review finding and the plan's Verification section.
- Decision: after its asynchronous steps, an outside freeze rechecks that the tab's Agent session and binding state are still the ones it froze, with the existing `prospectiveFileToolLookupSourceIsCurrent`, and refuses with the existing superseded error. A superseded hydration result gets the same refusal. The removed outside lookup path made this check, and moving the freeze had dropped it. Source: review findings and plan section J.
- Evidence: the review loop ran four rounds. The first, from an empty selection, couldn't see the diff, because a deferred Agent Mode review refuses diff artifacts during discovery. The later rounds selected the changed files first and reviewed the attached diff. The last round's only finding was the deferred-target `git` guidance text, which item 2 changes.
- Evidence: an Oracle follow-up sent on a later turn of the reviewer session was refused because the chat "belongs to a different Agent Mode owner": each steer starts a new run, which owns new chats. Each follow-up therefore opened a new review chat whose message restated the earlier findings and their fixes.
- Evidence: the affected suites (`ContextBuilderNestedSelectionFrozenReviewTests`, `ContextBuilderSelectionTransactionTests`, `ManageSelectionSliceValidationTests`, `ContextBuilderGracefulShutdownTests`, `ContextBuilderWindowAdmissionTests`, `ContextBuilderACPSettingsPinPropagationTests`, `MCPExportWatchdogIntegrationTests`, `MCPControlMessagesTests`, `MCPReadAutoSelectionRecoveryIntegrationTests`) ran 101 tests with 0 failures after the review fixes, including both prompt-refresh tests. `make dev-swift-build PRODUCT=RepoPrompt`, `make dev-format`, and `make dev-lint` passed. Throwaway mutations, each reverted, failed the test written for them: skipping hydration, sending outside reviews through the final check, generating from the starting selection, checking roots only without bindings, and skipping the source recheck or its hydration guard.
- Evidence: the refactor review found two behavior-preserving cleanups, a named tuple type for the tab resolution and the snapshot initializer's own binding-state default, and both were applied.
