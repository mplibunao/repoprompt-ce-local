## 1b. Give `hooks.json` its own projection manifest

- Decision: `hooks.json` gets its own manifest, `.repoprompt-hooks-projection.json`, and `.repoprompt-agents-projection.json` again lists only `AGENTS.override.md` and `AGENTS.md`, as on `main`. A build rejects a manifest that lists a file it doesn't know and then fails every Codex launch. Every branch's debug build on a machine shares one debug profile, so a single manifest would break Codex in every other branch's debug build until it rebased. Source: user (via the parent session).
- Decision: one reconcile routine runs once per file set, instructions first, so a conflict on `hooks.json` neither blocks nor undoes the instruction copies. Each set stays all-or-nothing on its own, and five error messages that said no file changed now name only the file or manifest at hand. The change is folded into item 1's commit, so no commit on the branch has the single-manifest form. Source: orchestrator judgment.
- Decision: a build without this change ignores the hooks manifest and the copy, and its projection works as before. Its Codex loads the copy as a `user` hook, which its project-only gate never offers, so the hook is skipped while untrusted and runs only when its exact definition is already trusted in that home, as when a newer build approved it. No launch fails or hangs. This was read from `origin/main`'s projection, which lists only the two AGENTS files, and its `CodexHookTrustModels.swift`, which offers only `project` hooks and decodes every source. Source: orchestrator judgment.
- Decision: the production rollback unit needs no change. `Scripts/local_release_archive.sh` archives every top-level Application Support entry except `DebugApps`, `Rollbacks`, and `Conductor`, so `Codex/` with both manifests, the copy, and its trust in `config.toml` is restored together. Source: orchestrator judgment.
- Evidence: `CodexGlobalFilesProjectionTests` (10), `CodexRuntimeAuthorityTests` (9), and `CodexExecAgentProviderRuntimePreparationTests` (1) pass. Running hooks first fails the ordering test, and merging `hooks.json` back into the instructions set fails the ownership, copy, and ordering tests. Format and lint were clean, and the correctness and refactor reviews found nothing to change.

- Decision: discovery warnings never block. When the gate has nothing to review, it appends one transcript notice built from the bounded summary that the discovery-failure message also uses. ## 3. Show hook source and matcher at approval; source-neutral copy

- Decision: hook metadata decodes the optional `matcher`. A missing key or null becomes nil, a string is kept exactly, and any other type is rejected. The schema contract lists `data[].hooks[].matcher` as optional and nullable, as the Codex 0.159.0 schema reports it. Source: approved plan.
- Decision: the review hook carries the raw `source` and `matcher`, and one `sourceLabel` ("Global (user)", and "Project" since item 7) and one `matcherDisplay` feed both the card and the MCP interaction. The reported `sourcePath` is shown unchanged. Source: approved plan.
- Decision: every hook-approval string says "Codex hooks" rather than "project hooks", and the card says global hooks are edited in `~/.codex/hooks.json`. Raw identifiers, settings keys, response parsing, and request identity are unchanged. Source: approved plan.
- Evidence: `CodexHookTrustTests` (3), `CodexHookGateTests` (2), `AgentRunMCPToolServiceRespondDiagnosticsTests` (6), `CodexHookReviewCardStateTests` (4), and `AppSettingsMCPServiceAgentModeSettingsTests` (9) pass. The decode and MCP snapshot tests fail when the decoder trims the matcher or the details show the raw source. `make dev-codex-schema-check` checks against the Codex on `PATH`, which is 0.166.0. `Scripts/check_codex_app_server_schema.py` run directly against the bundled 0.159.0 also passes, with 45 methods, 196 parameter paths, and 94 response paths. Format and lint were clean, and the correctness and refactor reviews found nothing to change.
- Deferred: the default `agent_run` text showed none of these details, because `ToolOutputFormatter` had no `hook_approval` case. That predates this branch; item 3b fixes it.

## 3b. Show hook approvals in the default MCP `agent_run` text

- Decision: add this item to the run. `ToolOutputFormatter.formatAgentControlRun` had no case for the `hook_approval` interaction kind. An MCP caller's default `agent_run` text for a paused run showed only a generic "Provide response" line, and the hook keys, details, and allowed responses reached a caller only through `_rawJSON`. That affected project hooks before this branch. Now that global hooks pause every MCP-started Codex session once per hook definition, the gap would stall orchestrated runs. Source: user (via the parent session).
- Decision: the case lists the allowed responses from the interaction's options, the `Error` and `Warning` details, the `hook_keys` syntax for `approve_selected`, and each hook's key, event, source, source path, matcher, trust, hash, and full command. A multiline command goes in a fenced block so its line breaks survive. The details are read from the `Hook N <Field>` labels `AgentModeViewModel` writes, and the helper's comment names that coupling. Source: orchestrator judgment.
- Decision: every value a hook or Codex supplies is escaped before printing, because project hooks come from repository content. A line break in a key, path, matcher, or Codex error could otherwise forge a hook entry or an "Allowed response values" line in the text an agent reads before it trusts hooks. Line breaks become `\n`, and other control and bidi formatting characters become `\u{XXXX}`. Commands keep their fenced line breaks and tabs. Source: automated security review.
- Decision: a review of the whole branch found three more consent gaps, now fixed. The code-span delimiter counted backticks by grapheme, so a combining mark could close a span early; it now counts Unicode scalars. The approval card showed hook text verbatim; it now uses the same display-only escaping helper as the MCP text, `String.escapedForDisplay` in `Sources/RepoPrompt/Infrastructure/Utilities/String+DisplayEscaping.swift`, keeping line breaks only in the command. The default MCP text left out the interaction context that says trust is profile-wide; it now renders that context. Raw values still drive identity, `hook_keys`, and trust writes. Source: branch review.
- Decision: the display escaping also covers every format character (Cf), the whole tag block U+E0000-U+E007F, and both variation-selector ranges. Zero-width, tag, and variation-selector characters can carry text an agent reads and a person doesn't see. The cost is that emoji joiners and presentation selectors in hook text show as escapes. Source: automated security review.
- Evidence: `ToolOutputFormatterWorktreeTests` (20) and `AgentRunMCPToolServiceRespondDiagnosticsTests` (6) pass, and format and lint are clean. For one untrusted user hook, the default poll text grows from 547 to 1,114 characters (55 to 100 words). The `tools/list` entry is unchanged. Two correctness review rounds fixed one finding (multiline commands), and the refactor review found nothing to change.
