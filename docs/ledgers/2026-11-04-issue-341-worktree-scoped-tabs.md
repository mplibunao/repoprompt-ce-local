# Run ledger: worktree-scoped tabs

Request: issue #341 · Plan: `outside-context-builder-worktree-reviews-2026-11-03.md`, Part 2 only

The run lets an MCP caller outside Agent Mode create a compose tab scoped to a git worktree of a loaded root with `manage_workspaces` `create_tab`, so that every tool routed to the tab, including `context_builder` and `oracle_send` follow-ups, reads the worktree. It is the top layer of a stack on PR #338 (issue #260) and PR #333 (issue #332).

## 3. Oracle follow-ups

- Decision: `oracle_send` packaging takes its lookup source from the snapshot's `fileToolLookupSource`, so a follow-up on a scoped tab reads the worktree; before, it built the source from the session alone and refused. Git freezing passes the real Agent session when there is one; for outside callers that is provenance only, which nothing observes. Source: approved plan section F; design critique.
- Decision: `oracle_send` refuses a follow-up whose chat's tab isn't an open compose tab, before packaging, for every chat, scoped or not; a stashed tab counts as gone. The text: "Chat '<id>' can't continue: its tab was closed or stashed. The follow-up was not sent. Start a new chat in the tab you want with {"message":"<message>","new_chat":true}." The plan said such a follow-up continued in the caller's tab. It didn't: `locateOrCreateChat` refused it after packaging the caller's tab, with "Chat with ID '…' belongs to a different tab". So the change moves the refusal earlier and names the cause. Source: approved plan section F; design critique for the stashed tab; implementing agent's finding and wording.
- Decision: a connection's one-shot window-route tab hint, which `_windowID` calls such as `rpce-cli -w` carry, no longer conflicts with a binding made during the same call; an explicit `context_id` hint still fails closed. Without it, an `oracle_send` follow-up from a fresh `-w` connection moved the connection to the chat's tab and then refused its own window hint. Commit `a98967d07` had fixed the same conflict for connections bound before the call and named this case as a limitation. Source: implementing agent's root-cause finding; outside the plan's file list.
- Decision: `MCPUnavailableWorktreeDiagnostic` names no owner: "Tab 'X' (window N) can't be used: its worktree 'x' is missing from disk.", and without route context "The addressed context's worktree 'x' is missing from disk." PR #333 had already removed the Agent wording the plan quoted, so the plan's intent was applied to the current text. #332's read, bind, and mutation tests each run over an Agent-session owner and a tab-scope owner. Source: approved plan section H; implementing agent's judgment.
- Decision: review round 1 found two defects, both fixed. The run-handover branch of `resolveTabContext` still refused a window-route hint after a handover moved the binding; one helper, `hint(_:conflictsWith:)`, now checks both branches. And `new_chat: true` with a `chat_id` whose tab was gone hit the new refusal, which the refusal's own advice would have triggered; it now creates a new chat in the caller's tab. A `new_chat` call whose old chat's tab is open still moves to that tab first, as before. Source: review findings; implementing agent's judgment for the open-tab case.
- Decision: the handover branch has no test of its own. Both branches call the same helper, which the follow-up test covers through the bound branch, and no test in the suite drives a run handover; a fixture for one is out of proportion to a case that predates this change. Source: review finding, declined by the orchestrator.
- Evidence: round 2 found nothing above the declined coverage gap, and the refactor analysis found nothing worth changing.
- Deferred to item 4: the advertised `oracle_send` `chat_id` description says the chat continues "in the current tab or current context"; for outside callers it moves to the chat's tab.
- Evidence: `testScopedBackgroundTabFeedsContextBuilderAndOracleFollowup` now ends with a review-mode follow-up from a new connection after the visible tab changes, and checks at the outgoing request that it carries the worktree file and diff marker and not the main checkout's marker. `testOracleFollowupRefusesWhenChatTabIsGone` checks the message, that no request is sent, and that the binding, selection, visible tab, and chat's tab are unchanged. Throwaway mutations, each reverted, failed the matching test: a session-only packaging source, no window-route hint exemption, a silent return instead of the refusal, missing-folder evidence only for session owners, and a session-only mutation classifier. 10 affected suites ran 183 tests with one failure, the #274 test (`workspaceActivationFailed`), which then passed alone and in its suite.
