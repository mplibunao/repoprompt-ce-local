# Run ledger: stale agent worktree error

Request: issue #332 · Plan: `stale-worktree-authority-error-2026-11-03.md`

Make MCP file tools and `bind_context` report a specific, non-retryable `worktree_scope_unavailable` error that names the missing worktree and the tab, in place of the generic `workspace_authority_unavailable`, when a tab's Agent Mode session is bound to a worktree whose folder was deleted. The refusal stays: no fallback to the canonical checkout.

## 1. Read path and `bind_context` name the missing worktree

- Decision: reuse the code `worktree_scope_unavailable` for a confirmed missing folder, because mutations already return it for this condition. The new case is `retryable: false` with no `retry_after_ms`, and generic cases keep 1,000 ms. Source: approved plan and user.
- Decision: the message names the tab by name and `context_id`, plus the window, and the worktree by `visualLabel`, `worktreeName`, `branch`, or `worktreeID`, with the logical root's name and no absolute paths. Source: user (tab name) and approved plan.
- Decision: the resolver throws a new `AgentWorkspaceLookupContextResolutionError.unavailableWorktree` whose description equals `.unavailableProjection`, so `oracle_send` and the agent-run review source keep their generic text and never print the worktree path. Source: approved plan.
- Decision: a failure names a worktree only when `validateBindingsAvailable` confirms the folder is missing, at the two lookup catches and in `FrozenFileToolAuthority.validate`. When the folder disappears during a call (projection materialization, the store's scope check, `FrozenFileToolAuthority.capture`, the post-resolution freshness checks, or `bind_context`'s final gate), the generic, retryable error stays, and the next call names the worktree. Source: user and approved plan.
- Decision: the read test lives in `WindowRoutedFileToolIntegrationTests` on `PersistentMCPTestFixture`, because a plain `WindowState` has no domain routing to drive read tools over a connection. Source: code (`WindowState.swift:366`).
- Decision: `read_file`'s formatter renders any reply with an error code as a failure ("Read refused" when not retryable). Before, it showed the failure view only for retryable replies, so this refusal looked like an empty successful read. Source: orchestrator judgment.
- Decision: the frozen branch rechecks the binding source after `validate` and reports `.superseded` if it changed, and a tab name that looks like a path is left out of the message. Source: item review findings.
- Decision: standalone headless needs no change, because it has no compose tabs and doesn't resolve file authority through worktree bindings. Source: approved plan (code check of `DirectHeadlessCapabilityBackends.swift`).
- Evidence: `BindContextFileAuthorityTests` passed 22 of 22; the focused run over `BindContextFileAuthorityTests`, `WindowRoutedFileToolIntegrationTests`, `MCPReadMutationPathContractTests`, `BindContextRoutingAuthorityTests`, `WorkspaceRootBindingProjectionTests`, and `ToolOutputFormatterWorktreeTests` passed 115 of 115 (two earlier runs hit the known flake #274 in `testNewWindowSwitchReusesPreferredWindowAlreadyShowingWorkspace`); `MCPDomainReadToolProviderTests` passed 5 of 5; `make dev-format`, `make dev-lint`, and `make dev-swift-build PRODUCT=RepoPrompt` passed. Each new test failed against a temporary reintroduction of the defect it targets.

## 6. Shorter refusal text and a narrower code-structure retry rule

- Decision: the refusal's only job is to let the agent tell the user to switch tabs, because the app's UI already marks the missing worktree. With a routed tab it reads "Tab '<name>' (window <N>) can't be used: its Agent Mode worktree '<label>' is missing from disk. Retrying won't help. Tell the user so they can switch to another tab."; without one, "The Agent Mode session's worktree '<label>' is missing from disk." followed by the same recovery. The `context_id`, the `worktree_id` suffix, the root name, "No canonical checkout was used.", the routing explanation, and the `bind_context` steps are gone. The code, `retryable: false`, the missing `retry_after_ms`, the label fallback chain, and the path filter stay. Source: user.
- Decision: `get_code_structure` drops "Resolve the reported issue, then retry." only when every issue is a non-retryable `workspace_authority` issue. This supersedes item 4's broader rule, which also removed the line from non-retryable seed and graph failures. Source: user, after a review of the agent-facing changes found the regression.
- Decision: a tab whose name is withheld as a path reads "A tab in window <N>", a binding with no safe label drops the quoted label, and `bind_context` reuses the same message. `RouteContext` no longer stores the tab's `context_id`, because nothing reads it. Source: orchestrator judgment; engineer judgment for the `context_id` removal.
- Evidence: the `read_file` message went from 749 to 182 characters, `apply_edits`'s error plus suggestion from 784 to 217, and `file_search`'s from 748 to 181. `ToolOutputFormatterWorktreeTests` now includes an `empty_seeds` case that failed against item 4's rule. The focused run over seven suites passed 116 of 116; runs that included `BindContextRoutingAuthorityTests` hit the known flake #274. `make dev-format`, `make dev-lint`, and `make dev-swift-build PRODUCT=RepoPrompt` passed, and the item's `context_builder` review found nothing.
