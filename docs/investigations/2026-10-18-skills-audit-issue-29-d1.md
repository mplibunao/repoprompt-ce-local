# Skills audit 2026-10-18: issue #29 run-ledger prompt wording

> Investigation report, observed 2026-10-18 on the draft run-ledger wording of the built-in Orchestrate and Optimize prompts and the toolkit's `rp-orchestrate-loop` skill for issue #29. It records what was true then. Where it disagrees with a current document, the current document is right.
> Current guidance: [CONTRIBUTING.md](../../CONTRIBUTING.md), Plans and committed records.

## Scope

The `+` lines of the run's draft wording change, a local working packet, read in its four `after/` copies:

- `after/repoprompt-ce/Sources/RepoPromptShared/Workflows/WorkflowPrompt+Orchestrate.swift` (O1–O9, O5a)
- `after/repoprompt-ce/Sources/RepoPromptShared/Workflows/WorkflowPrompt+Optimize.swift` (P1–P11)
- the toolkit's `rp-orchestrate-loop` skill (L1–L11)
- `after/repoprompt-ce/Sources/RepoPromptShared/Workflows/WorkflowPromptSharedFragments.swift` (O11)

Neighbours read for the restated-rules, pruning, and cuts checks, with no findings of their own: the packet's `before/` and `previous-draft/` copies, its list of cut passages and its change notes, the run's local plan (its decisions, design, and edge cases), the two global agent instruction files at the toolkit's `main`, and the RepoPrompt CE sources on `main` for platform claims.

Usage window: 2026-09-18 to 2026-10-18 for Claude Code transcripts; all time for `skillUsage` and the Codex logs.

Every file in scope is wording the user's instructions reserve for his approval (`AGENTS.md` "Changes to skills and workflow prompts" for the built-in prompts; a toolkit issue for `rp-orchestrate-loop`), so every disposition below is a proposal and ends with `(waits for approval)`. Findings on the five passages the task lists as approved word for word carry the marker `approved text`. Line numbers are those of the `after/` copies. The task gave these decisions as settled; they are applied as given and are not findings:

- The prompts never say whether to commit the ledger or the scoreboard; each repository's own docs decide.
- Deferrals are recorded only in the run ledger; the prompts never mention a tracker, issues, or filing.
- A commit in another repository names that repository and its branch, and adds its pull request once one exists.
- The ledger section in the built-in prompt and its copy in the loop skill are the same text on purpose: the two are owned separately, and each must work in sessions that never load the other.
- The parked-decision bullet repeats the global rule on purpose, because RepoPrompt Agent Mode doesn't load the global files.
- "A single-item run still writes one." stays: without it, the shared "1 item = skip the ceremony" guidance reads as permission to skip the ledger.
- The run ledger links the Optimize scoreboard (issue #29).
