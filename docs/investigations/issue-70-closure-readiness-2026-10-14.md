### Verdict on the hypotheses

The suite remains unbounded below the 60-minute conductor and 45-minute CI job timeouts (E). Acceptance criterion 4 is not met.

## Root Cause
Before #52 (baseline `63ab6007`, which already had #38's 5-second Default settle and #57's fresh sandbox), two owners created the first-run Default workspace and neither was joined before activation: the manager's unretained creation `Task` and the presentation bridge's initial projection. The bridge's `projectInitial` issues its own Default create, re-snapshots, and then replaces the manager's `workspaces` wholesale through `applyDomainWorkspaceProjection` (`WorkspaceManagerViewModel.swift:5530-5624` on `145c0160`); its event loop starts only after that (`DomainWorkspacePresentationBridge.swift:293-305`). A stale initial projection landing after the fixture had appended and switched to its own workspace could remove that workspace from `workspaces` mid-admission. Depending on timing, that yields `.sessionIdentityChanged` or a `workspace_changed_after_capture`/`_after_save` save rejection, and both surface as #70's "durably accepted" message (`AgentModeViewModel.swift:8936-8938`). The `testCanonicalAdmissionRefresh*` tests hold a gate inside the canonical refresh, which widens exactly that window. A fresh profile changes timing (no chat or agent-session sidecar directories yet for Default), not admission inputs: conductor isolates only `REPOPROMPT_TEST_SANDBOX_ROOT`, and the fixture's workspace storage is per call either way.

Confidence: the structural defect is confirmed and is the only fresh-profile-sensitive route found; the exact interleaving is inference, because the historical failures recorded only the generic message, not the rejection reason.

The hang has no separate root cause: any admission error before provider dispatch parks `testSecondWindowCannotStartPublishedProvisionalSessionBeforeAcceptance` at line 918, and about 20 other awaits in the suite and fixture have no deadline (Investigator Findings E).

## Preventive Measures
- Put the durable-admission rejection reason (the receipt's reason code) in the error tests see. #70's failures carried only the generic message, so attribution had to be reconstructed from source.
- Every continuation-based test gate gets a deadline; waiting on a gate must also observe failure of the task expected to reach it.
- Run XCTest under a progress-stall bound by default in `make dev-test` and CI, so a hang names the stuck test within minutes.
- When one bootstrap state has two owners, the barrier joins both. #38's settle waited on Default's canonical commit but not on the bridge's projection, which is why #70 survived it.
