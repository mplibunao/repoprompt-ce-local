The requirement, from MP in chat: agents should batch approved pull requests instead of cutting one release candidate each, because every candidate pays for a full validation run and hosted CI. A session that is handed a pull request was handed it so it can batch, not so it can cut a candidate. A promotion's `BUILD_NUMBER` bump should not need a question or a candidate of its own. When MP approves a pull request, the agent should ask him whether to land it now or batch it, naming batching, the way a team gets a go signal before it releases.

The question: does the final text tell an agent exactly what to do when MP approves a pull request, when a pull request is handed to another session, and when MP asks to promote a build?

## Verdict

The final text has the right shape: nothing lands without MP's go signal, the agent asks one question that names batching, and one candidate takes every pull request that is ready. Seven passages still leave an agent guessing or asking MP twice.

- **MP approves a pull request.** The agent asks the question, but the list the question shows isn't the list the landing skill needs before it can count MP's answer as confirmation, and the skill tells the agent not to start until after the go signal, so MP gets a second question (rows 6, 13, 14). "Hold" says what happens to the pull request, not what the agent does next (row 9). The agent asks even when MP's approval already says which (row 5). In `AGENTS.md`, the rule binds only the agent that owns the pull request, and "without his answer" covers only the question (row 2).
- **A pull request is handed to another session.** Covered. When MP approves and hands over in one message, both sessions have a reason to ask (row 5).
- **MP asks to promote a build.** Covered only when MP asks before the batch is cut. Three of the four bump-only candidates landed 17 to 82 minutes after a batch, so the question should offer promotion (row 5). A promotion agent reads `$rpce-release` and `docs/releasing.md`, which never say how the build number is chosen or how the bump lands, and `$rpce-release` tells it to ask MP for missing inputs (row 17).
